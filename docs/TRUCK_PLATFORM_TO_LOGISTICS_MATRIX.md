# Truck Platform × Logistics 新版功能差異矩陣

日期：2026-11-17

## 決策基準

沿用既有 `xk-truck-platform` 的業務邏輯與經核對規則，另建新版。舊平台是唯讀參考來源；`codex-xk-logistic` 是新版規格與實作 repo。沿用表示保留業務語意，不表示複製程式碼或視為已驗收。

本矩陣以固定來源版本與目前可讀規格為依據。舊版 README 所列功能不等同程式完整、啟用或通過驗收；需實際核對的項目標為「部分／待查證」。

## 功能對照

| 領域 | 舊版證據與狀態 | 新版目標 | 處理方向 | 缺口／驗收重點 |
|---|---|---|---|---|
| 共用帳號與權限（UPMS） | G1 README／業務定義列出使用者、角色、權限及 JWT；實際端點與權限完整度待查證 | 管理員、調度員、司機三角色，依公司及本人任務範圍授權 | 沿用角色與權限的業務需求；重新設計認證、授權與 API | D01、D02 未完全定案；驗收未授權 API、停權即失效、司機資料隔離 |
| 字典與參數（ADM） | G1 有 ADM 模組及字典／系統參數模型；CRUD 完整度待查證 | 支援新版訂單、任務及車隊所需的受控選項 | 沿用必要領域選項；重新篩選字典內容及管理 API | 確認 MVP 必要字典、異動稽核及種子資料 |
| 客戶（CRM） | 舊平台訂單使用 customerUuid／客戶名稱快照；獨立 CRM 功能證據有限 | 客戶主檔及歷史名稱快照；聯絡人範圍依 MVP 決定 | 沿用客戶識別與歷史快照語意，重建模型與 API | 客戶來源、聯絡人、重複資料及資料遷移待確認 |
| 訂單核心（OrderCore） | G1 有 OrderCore 與高階 OPEN／CANCELLED／CLOSED 概念 | 訂單核心生命週期與 TOM 保持一致 | 沿用概念，核對跨模組交易與唯一單號規則後重建 | 跨模組一致性、取消／結案守衛與交易原子性待驗收 |
| 運輸訂單（TOM） | G1 有 IMPORT／EXPORT／LOCAL；舊 TomOrder 為單一起終點。README／盤點指出列表、明細等控制器入口被註解 | 一單多貨櫃／貨物項目、多段任務、受理／取消／結案及歷程 | 沿用訂單類型與有效業務語意；重寫單一起終點限制、API 與狀態機 | D03／D04；欄位必填時點、草稿／受理條件及整單結案規則 |
| 車隊管理（FMS） | G1 有車輛、司機、派工；DispatchService 狀態操作直接更新，盤點未見足夠前態／占用／照片檢核 | 車輛與司機主檔、有效派工、狀態與資源占用歷史 | 沿用主檔及派工領域；重寫狀態守衛、交易、占用與稽核 | 車輛／司機何時釋放、競爭派工、撤改派及出發後異常需驗收 |
| 多貨物／多段任務 | 舊 TomOrder 無法直接表達新版多櫃、多段與多次派工；本機舊前端摘要含櫃數及任務線索 | 每訂單多項目；每項目可有有序前置任務；每任務最多一組有效派工 | 新版新增／重構，保留領域語意而不搬舊資料結構 | 真實進口／出口／國內匿名案例；任務依賴、合載與無訂單任務邊界 |
| 司機手機流程 | G1 README 的 API 清單不足以證明手機閉環；新版尚未實作 | 響應式手機網頁：本人派工、出發、回報、補件／完成 | 新版新增 | iOS Safari／Android Chrome 實機；離線是否排除；本人範圍及重送處理 |
| 作業照片／附件 | 舊平台是否有私有照片與存取控制待查證 | 每段作業憑證照片、驗證後才可簽收，依派工授權讀取 | 新版新增；不沿用舊公開連結或未核實資產 | 照片數量／必填時點、格式大小、保存期限、儲存供應商與復原驗收 |
| API／前端契約 | 舊 Controller 有停用入口；舊 UI 摘要有 Mock 與型別不一致風險 | 前後端分離、單一 OpenAPI 契約、明確錯誤與分頁行為 | 重寫契約；參考舊頁面流程但不搬假成功 | OpenAPI 待決策後建立；API 失敗不得回退為假成功或空清單 |
| 資料庫／認證 | G1 POM 有 JPA、MySQL driver、Spring Security、JWT 依賴；不代表正式 DB 或設定可沿用 | 新版資料庫、認證與資料存取獨立決策 | 不自動沿用技術；依來源資料、維運能力和產品需求評估 | D01／D07；MySQL／PostgreSQL、JWT／Session、JPA／JDBC 分開記 ADR |
| 部署／維運 | 舊版執行部署、備份與還原狀態待查證 | 新版具 staging／production、照片儲存、備份與還原責任 | 新版重新設計，舊設定不複製 | D10；主機／NAS、網域、容量、預算、責任人及 RPO／RTO 待確認 |

## 模組映射原則

| 舊平台 | 新版規劃 | 說明 |
|---|---|---|
| xk-base | 新版共用核心候選 | 參考 ApiResult、例外、UUID／稽核等概念；逐項審查依賴、授權及與公司共用模組策略的相容性，不直接複製 |
| UPMS | UPMS | 領域需求可沿用；認證／授權政策重新核准 |
| ADM | ADM | 只納入 MVP 所需字典與參數 |
| OrderCore | OrderCore | 保留高階訂單共同語言；重新驗證跨模組一致性 |
| TOM | TOM | 訂單流程擴充到多項目、多任務 |
| FMS | FMS | 主檔概念可沿用；派工狀態、占用與歷程重寫 |
| 無／待確認 | CRM、任務項目、照片資產 | 依新版閉環新增；資料關聯與存取規則需核准 |

## 已確認與待確認

已確認：另建新版；舊平台只作業務邏輯參考；新版規格／實作留在 Logistics repo；已有對話確認的一單多項目、多段任務、單公司內部角色、司機手機照片回報及派工規則作為規劃基準。

待確認：D01～D10 尚未全部決策；舊版實際執行功能、正式資料庫與資料擁有人、是否遷移歷史資料、精確技術版本、部署資源、預算及維運責任人仍需證據或業主確認。
