# ADR-0005：內部瀏覽器登入採用 Session 與 CSRF

- 狀態：Accepted（使用者已採用）
- 提案／查核日期：2026-11-17（Asia/Taipei）
- 決策者：使用者陳祿元
- 核准日期：2026-11-17（Asia/Taipei）
- 確認依據：本次對話回覆「是！採用」，採用前一則列出的六項技術方案。
- 主要任務：[Issue #4](https://github.com/xk2022/codex-xk-logistic/issues/4)
- 整體提案：[技術選型與資料接續建議](../TECHNOLOGY_AND_DATA_PROPOSAL.md)

## 背景與選項

已確認第一版是單公司內部及司機手機網頁；目前沒有原生 App／第三方 API 身份授權需求證據。候選為伺服器 Session 或 token 方案，與是否採 PostgreSQL／JPA 無綁定。若後續新增外部用例，再重新評估，不直接複製舊 JWT 設定。

## 已採用方案

採用同源 HTTPS 服務下的 Session＋CSRF，Cookie 採相應保護，讓瀏覽器身份、登出／停權失效與 CSRF 更新有一致流程。精確存放、逾時、帳號復原、代報與各動作授權仍待政策定稿。

## 影響與驗收

Spring Security SPA 整合需處理登入／登出後 CSRF token 更新。採用本方案仍須證明未登入／缺 token 拒絕寫入、本人任務與照片隔離、改派後可見範圍、停權及登出失效、過期畫面明確處理。上述細節與驗收仍待完成。Session＋CSRF 的認證技術選擇已由使用者確認，無須重複詢問；精確逾時、帳號復原、例外代報及各操作資料範圍仍依 D02／D10 定稿。本輪只更新決策紀錄，未修改任何安全設定。

## 依據與狀態

[Spring Security CSRF／SPA 文件](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。本文件記錄已採用方案與工程影響；登入執行能力仍待實作驗收。
