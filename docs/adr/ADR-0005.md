# ADR-0005：內部瀏覽器登入候選 Session 與 CSRF

- 狀態：Proposed（待使用者選定）
- 提案／查核日期：2026-11-17（Asia/Taipei）
- 決策者／核准日期：待確認

- 整體提案：[技術選型與資料接續建議](../TECHNOLOGY_AND_DATA_PROPOSAL.md)

## 背景與選項

已確認第一版是單公司內部及司機手機網頁；目前沒有原生 App／第三方 API 身份授權需求證據。候選為伺服器 Session 或 token 方案，與是否採 PostgreSQL／JPA 無綁定。若後續新增外部用例，再重新評估，不直接複製舊 JWT 設定。

## 建議方案

建議同源 HTTPS 服務下使用 Session＋CSRF，Cookie 採相應保護，讓瀏覽器身份、登出／停權失效與 CSRF 更新有一致流程。精確存放、逾時、帳號復原、代報與各動作授權仍待政策定稿。

## 影響與驗收

Spring Security SPA 整合需處理登入／登出後 CSRF token 更新。採用本方案仍須證明未登入／缺 token 拒絕寫入、本人任務與照片隔離、改派後可見範圍、停權及登出失效、過期畫面明確處理。上述均為待定稿／待執行驗收。本 repo 認證／授權政策須使用者確認後才實作；本輪只寫提案，不改任何安全設定。
