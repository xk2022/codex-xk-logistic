# ADR-0001：Truck 與 Logistics 以相同業務邏輯另建新版

- 狀態：已接受（產品重建方向）
- 決策者：使用者陳祿元
- 決策日期：2026-11-17（Asia/Taipei）
- 工作追蹤：[Issue #4](https://github.com/xk2022/codex-xk-logistic/issues/4)

## 背景

舊 xk-truck-platform 包含共用核心及物流業務程式；codex-xk-logistic 已整理新版多項目、多段、司機手機回報與維運需求。舊碼的單一起終點、停用訂單入口及直接狀態操作不能直接滿足新版閉環，來源證據見 [程式核對](../SOURCE_CODE_AUDIT_20261117.md)。

## 選項

1. 在舊 Truck 上持續增加新版功能。
2. 合併兩個 repo 並搬入舊程式。
3. 保留舊平台作業務參考，在 Logistics repo 重新實作新版。

## 決策與依據

使用者明確要求「Truck 與 logistics 一起評估整合」，並選定「相同邏輯另建新版」，採選項 3。

xk-truck-platform 是參考來源；codex-xk-logistic 是新版產品規格與實作 repo。重用經核對的業務語意、來源與驗收需求，重新實作程式。本輪不改寫舊庫，也不以舊版類別存在宣告新版完成。

## 影響

- 維持需求及程式來源的固定版本與差異矩陣，讓模型改動可追溯。
- 新版需要自己的 API、資料結構、授權、交易與驗收證據。
- 不用舊報告完成率推估新版進度。
- 另建新版不代表刪除舊系統、停止營運、放棄資料保留或不需遷移。
- DB、認證、ORM、migration、照片儲存與部署另記技術決策；本 ADR 不核准這些方案或正式操作。
