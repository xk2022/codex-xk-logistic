## 背景與選項

使用者已確認相同業務邏輯另建新版。選項包括沿舊 Boot 3.5.x、評估 Boot 4.0／4.1、新增其他後端技術或拆微服務。既有 repo 使用 Java 21／Boot 3.5.7；本次官方查核顯示 3.5 開源支援已結束。這是新版建置評估，不修改舊平台依賴。

## 建議方案

建議 Java 21＋Spring Boot 4.1.x 的模組化單體，前端 React＋TypeScript＋Vite，前後端分開建置、同源反向代理 /api。Service 遵循本庫 Interface＋Impl 與交易邊界規範；現階段將 UPMS／ADM／CRM／OrderCore／TOM／FMS 視為同產品領域，尚不抽成跨產品共用服務。

## 影響與驗收

本次系統需求頁顯示 Boot 4.1.2 可搭 Java 21，仍要在開工前鎖定修補版及 BOM 管理相依，驗證安全、ORM、Flyway、API 文件與前端建置整合。規格與環境門檻完成且有實作交辦後，才建立骨架並執行建置／空庫啟動與第一片驗收。本輪沒有產生 POM、安裝依賴或執行測試。DB、ORM、認證及 migration 各自選定，不因採用本 ADR 一併核准。

## 依據與狀態

[Spring 3.5.16 支援公告](https://spring.io/blog/2026/06/25/spring-boot-3-5-16-available-now/)；[Spring Boot 系統需求](https://docs.spring.io/spring-boot/system-requirements.html)。框架方案是本案提案，官方相容範圍不等於此產品整合已測試。
