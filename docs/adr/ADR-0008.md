# ADR-0008：首片草稿API的角色與資料範圍

- 狀態：Accepted
- 決策日期：2026-11-17（Asia/Taipei）
- 決策者：使用者陳祿元
- 主要任務：[Issue #4](https://github.com/xk2022/codex-xk-logistic/issues/4)
- 確認依據：對前輪ACC-P01／P02權限表及「是否採用」詢問回覆「是。下一步」。

## 已採用決策

採用[ACC-P01／P02](../FIRST_SLICE_ACCESS_AND_TEST_PLAN.md)：管理員與調度員可以建立、列表、明細、完整替換及只讀檢查本公司訂單草稿；司機不開放這五項整單API，後續僅取得本人有效派工所需摘要。單公司範圍、當前角色、帳號及資料權限由伺服器查核，不能由客戶端宣告。

管理員與調度員同樣要通過OPEN＋DRAFT、有效客戶、版本、同單參照與重送等守衛。採用草稿權限不授予受理／派工／轉態、覆寫歷史、修改角色或代司機回報的權限；司機摘要／回報端點依後續切片另訂。

## 契約表示與驗收

[OpenAPI](../api/openapi.yaml)的sessionAuth仍表達已採用的Session認證；逐operation以x-authorization-policy寫明角色／資料範圍，不把角色名稱塞進Cookie認證的OAuth scopes。ADMIN／DISPATCHER／DRIVER是契約邏輯標籤，實際Spring Authorities映射與多角色兼任的解析方式仍需實作／帳號方案核對，不能假定現有DB已有這些角色代碼。

[機器可讀權限表](../api/ORDER_DRAFT_ACCESS_POLICY.json)包含五operation×三個單角色的15個對照；這是文件契約，不是授權程式或已通過HTTP測試。未登入401；有登入但無操作角色403；具操作權限後在授權範圍查無資料404。拒絕及成功重播均依目前權限重驗，不能透過key取得已失去權限的資料。

## 採用界線與後續

本次僅採用ACC-P01／P02。DEV-P01環境、首次帳號建立、密碼／Session／復原、多角色生效／切換、主檔管理及其他L2權限不是本次全部核准，見[首片啟動包提案](../FIRST_SLICE_STARTUP_PLAN.md)。原G1～G5的關聯前提保留；產品程式、DB與安全設定尚未建立，未執行部署或支出。

## 變更影響

API文件版本轉0.2.0，僅補核准的角色／資料範圍；paths、request／response schema與session／CSRF技術不變。新版API尚未實作或部署，沒有既有消費端遷移。本次修改可revert文件提交；不是撤銷已採用的業務決策，若要改權限需另記新決策。
