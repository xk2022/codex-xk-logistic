# Logistics 新版交付切片建議

日期：2026-11-17（Asia/Taipei）。主要任務：[Issue #4](https://github.com/xk2022/codex-xk-logistic/issues/4)。狀態：可審閱建議；未排定開工或承諾工期。

## 目標與已確認範圍

2026 年內交付是使用者目標。範圍基準為單公司、管理員／調度員／司機、一單多貨櫃／貨物項目、多段有前置依賴的任務、每任務最多一組有效派工、手機照片回報及派工至結案閉環。細節以 [決策紀錄](06-decisions-and-acceptance.md) 的已確認／待確認範圍為準。

本頁將完整第一版拆成可驗收工作，沒有將後續切片移出已確認 MVP，也沒有新增已核准的業務政策。

## 技術與資料接續輸入

使用者已採用 [T01–T05 技術方案](TECHNOLOGY_AND_DATA_PROPOSAL.md)，ADR-0002～0006 為 Accepted。第一片依 Java 21／Boot 4.1.x、React／TypeScript／Vite、PostgreSQL 17、JPA、Flyway、Session／CSRF 規劃；精確版本、相依整合、M01–M03 資料路線、業務欄位及環境前提仍須完成。T06 照片／部署仍是候選。

## 首片欄位與驗收輸入

已採用 [ORD-P01～P03首片規格](FIRST_SLICE_ORDER_SPEC.md)，並建立 [資料模型](FIRST_SLICE_DATA_MODEL.md)、[API工程契約](api/README.md)與合成正反例；保存草稿與只讀完整性分開。欄位業務例外仍待確認；受理動作／派工等不自動擴張本片實作範圍，也不改變完整MVP。

## 第一個開發切片：新版主檔與多段訂單可保存、可重讀

建議操作路徑：管理員／調度登入 → 建立或選取客戶與車司機主檔 → 建立含多個項目及各自多段任務的訂單 → 重新整理與重新開啟明細 → 查回同一組已保存關係。

第一片先證明新版的身份、資料邊界及多項目多段結構可持久化。派工／司機回報／結案接後續切片；第一片完成不算整個 MVP 完成。

| 交付 | 驗收條件 | 開工前輸入 |
|---|---|---|
| 技術 ADR 與可重建環境 | 每個選型、精確版本、啟動與依賴都有依據；空 DB 可重建 | D01 已採用；精確版本與相依需核對／驗證。D07、D10 中影響開發／測試環境的事實及其餘 G3／G4 門檻仍按執行入口 |
| 登入與必要角色／主檔 | 依核定資料範圍操作；未授權帳號不可新增或讀取；回應不包含認證敏感欄位 | D02 逐動作授權、D10 帳號復原策略 |
| 多項目多段的建立／列表／明細 | 合成案例一單兩項目、每項目兩段可重讀，關係與前置依賴不遺失；明示合成資料 | D03關聯子項、D04字典／例外、D08必要主檔；P01～P03最小必填基準已採用，草稿工程契約已建立 |
| 跨模組一致性及錯誤處理 | Core／TOM／項目／任務中途失敗不產生可見半筆訂單；重送結果依契約核對；API 失敗不得假成功 | 本片交易／重送／版本契約已建立；仍待實作與真實DB競爭／回滾驗證 |
| 對應證據 | 保留單元、DB／交易、授權與真實 API 介面操作結果；測試資料與環境明確 | 實作交辦與規格定稿後才執行；本頁不宣稱已通過 |

本片完成標準是從空環境可重現上述路徑及必要反例，留下版本與證據。本片endpoint及資料模型已有工程契約；實際DDL、設定與程式仍待關聯決策／開工交辦。
