## 建議分期

1. 規格確認：D01～D10、真實作業案例、角色矩陣、頁面欄位、資料關聯、狀態圖與 OpenAPI。
2. 基礎切片：前後端骨架、Compose、Flyway、登入與權限、客戶／車司機主檔。
3. 核心閉環：訂單建立→受理→任務→派工→出發→簽收→完工→結案。
4. 例外與品質：撤改派、權限／競爭／重送、手機操作、錯誤與效能驗收。
5. 上線準備：部署、備份還原、監控與資料搬遷（若核准）。

現在只完成文件整理，不進入第二步。工期需依 D03／D04／D08／D09 收斂後估算；不用舊報告數字當承諾。

## 核心驗收情境

| ID | 情境與預期 |
|---|---|
| A01 | 調度建立訂單後重新整理，訂單及 Core 仍一致存在；非法客戶不能建立 |
| A02 | NEW 才能受理；取消／結案訂單不能再受理或派工 |
| A03 | 同時用同一車或司機派兩個任務，依占用政策最多一個成功，另一個回 409 |
| A04 | 重送同一建立／派工 key，不多建立訂單或占用；同 key 不同內容被拒絕 |
| A05 | 無權限帳號直接呼叫 API 被拒絕；司機不能看或改別人的任務／照片 |
| A06 | 未出發不能簽收、未簽收不能完工；過期畫面不可跳轉狀態 |
| A07 | 若照片必填，缺照片／未完成上傳／格式不符／他人資產都不能簽收 |
| A08 | 完工依核定政策釋放車司機，保留操作者與時間；中途失敗全部回滾 |
| A09 | 若採多櫃多任務，其中一段完成不代表整單結案；所有必要任務完成才可關單 |
| A10 | 撤派／改派留史且不遺留舊占用；出發後取消依核定政策處理 |
| A11 | 同時編輯同筆資料，舊 version 回衝突；不存在、無資料與 API 失敗的 UI 清楚區分 |
| A12 | 登出／停權後 Session 無法再操作；缺 CSRF 或錯誤來源寫入被拒絕 |
| A13 | 日期跨台北午夜顯示與篩選正確；decimal 重量與單位一致 |
| A14 | DB 遷移從空庫可重現；如有移轉，筆數、關聯及歷史對照可核驗 |

以上是預期驗收，沒有任何一項因本次靜態閱讀而視為通過。測試以交易、授權與使用情境為主，另做真實 API 的瀏覽器閉環，不能以 Mock 展示取代。
