## 建議交付順序

1. 補齊關聯決策及案例，明確記錄模型、動作規則、角色／欄位與驗收條件。
2. 依已採用技術核對精確版本與相依組合；完成 [新版切片建議](REBUILD_DELIVERY_SLICES.md) 的其他前提後排首個開發工作。
3. 逐步完成多項目多段訂單、派工、出發／回報、資源釋放及行政結案。
4. 驗證例外、競爭／重送、授權、手機與照片流程。
5. 核定部署／資料接續方案，完成上線與還原驗收後另依正式操作授權辦理。

新版程式仍待關聯業務規格、資料／環境前提與實作交辦解鎖；技術基準已確認，精確相依仍須驗證。工期與估時基於新版可驗收範圍，不使用舊報告完成率或工時作承諾。

## 核心驗收情境

本節是驗收需求；精確狀態代碼、HTTP 契約與技術機制仍須在相應決策完成後定稿。

| ID | 情境與預期 |
|---|---|
| A01 | 調度建立訂單後重新整理，訂單及 Core 一致存在；非法客戶不能建立。 |
| A02 | 只有合法前態可受理；已取消／結案訂單不能再受理或派工。 |
| A03 | 同時用同一車或司機派兩個衝突任務，最多一個成功；另一個收到明確衝突結果。 |
| A04 | 重送相同建立／派工操作不多建訂單或占用；同 key 不同內容被拒絕；key 契約待定稿。 |
| A05 | 未授權操作被拒絕；司機不能看或改別人的任務／照片。 |
| A06 | 未出發不能完成該段回報；前置條件不足不能跳到下一段，過期畫面不得跳轉狀態。 |
| A07 | 依核定照片必填／驗證規則，缺照片、未完成上傳、格式不符或他人資產不能完成回報。 |
| A08 | 該段作業完成且確認人車可離場後，依核定角色與例外規則原子釋放並留史；中途失敗不得留下半筆占用。行政確認是獨立步驟。 |
| A09 | 多項目多段中某段完成不能當整單結案；整單必要任務／異常等結案條件須定稿並驗收。 |
| A10 | 出發前撤改派留史、不遺留舊占用；出發後走核定異常流程，不能直接取消繞過。 |
| A11 | 併發編輯收到明確衝突；不存在、無資料與 API 失敗的 UI 清楚區分。 |
| A12 | 依已採用 Session／CSRF 驗證登入／登出後 token 更新、缺少或錯誤 CSRF 的寫入拒絕及 Session 失效；停權／逾時／復原與詳細授權政策依 D02／D10 定稿並驗收。 |
| A13 | 台北日期跨午夜顯示／篩選與重量小數／單位正確。 |
| A14 | 新 DB 從空庫可重建；如需移轉，筆數、關聯、歷史及照片可核對。 |

以上均尚未執行產品驗收。舊碼觀察見 [程式核對報告](SOURCE_CODE_AUDIT_20261117.md)，不可用靜態方法存在或已合併文件代替測試通過。
