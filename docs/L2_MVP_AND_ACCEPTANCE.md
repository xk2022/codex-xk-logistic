# L2｜第一版範圍、角色與驗收提案

狀態：規格提案，待業務決策；未修改認證、授權或安全設定，未實作程式。使用者已交辦定義第一版邊界、角色資料範圍及司機手機／照片，並要求新版程式排在規格決策後；這不等於已核准以下具體政策。

## 依據與決策界線

依據為 [產品草案](03-product-spec.md)、[來源盤點](01-source-inventory.md)、[差異分析](02-gap-analysis.md)、[資料流程](04-domain-and-workflows.md)與 [D／A 清單](06-decisions-and-acceptance.md)。現有來源只支持需求候選，未證明舊系統已具備下列能力。本文的 L2-xx 是待執行驗收，不是通過紀錄。

| 決策 | 本次可審閱建議 | 核准前仍需確認 |
|---|---|---|
| D02 | 單一公司內部；管理員、調度員、司機三角色；不開放客戶／外包入口 | 實際是否有多公司資料隔離、外包司機及查詢人員；如有須重訂範圍 |
| D06 | 第一版含手機網頁及每段作業憑證照片；不做原生 App／離線回報 | 照片必填時點、例外代報人、手機與網路條件；照片政策如下 |
| D08 | 第一版有多櫃多段、派工與必要的地點文字／基本主檔；板車若需獨立占用才納首版 | 是否實際拆掛板車；若需要，不得以備註假裝已管理資源 |

第一版定義為「人工調度可完成進口、出口、國內的訂單→多櫃／貨物項目→多段任務→派工→司機回報→行政確認→結案」。個別狀態、資源釋放與先後段依賴以 L1 核定結果為準，不由本文件另訂第二套狀態機。L1–L4 規格、來源及上線責任未決前不開始新版程式。

## 角色操作及資料範圍矩陣

以下為擬定產品要求，核准後才落實為授權政策。角色可以由同一人兼任，但每次操作仍留實際帳號；不得共用司機帳號。

| 資料／操作 | 系統管理員 | 調度員 | 司機 | 範圍與驗收 |
|---|---|---|---|---|
| 帳號、角色、啟停、受控帳號復原 | 管理 | 無；只能查本人 | 無；只能查本人 | 管理員限本公司；復原留史，具體機制待 D10，L2-01／02 |
| 客戶、車輛、司機主檔 | 管理 | 新增、編輯、啟停 | 僅本人必要資料及當次任務車輛摘要；不可改主檔 | 不給司機全公司通訊錄／完整證照，L2-03 |
| 訂單、櫃項、任務建立／受理 | 管理 | 管理 | 僅有效派工所需摘要；不可改業務欄位 | 管理端全公司；司機只見該段標的、地點、時間、必要聯絡資訊及作業指示，L2-04 |
| 派工、撤派、改派 | 管理 | 管理，依 L1 合法狀態 | 查看本人有效派工；不可自選其他任務或改資源 | 改派後舊司機失去該派工明細與照片存取；不抹除稽核歷史，L2-05 |
| 出發、回報、本人上下線 | 可查；不冒用司機操作 | 可查；代報另走有原因與實際操作者的例外流程 | 本人有效派工；上下線只改本人 | 未授權代報不得以一般編輯繞過；停權即失效，L2-06 |
| 作業照片上傳／讀取 | 查核；不任意覆寫原檔 | 查核；例外補件需原因及實際操作者 | 僅本人有效派工上傳／讀取 | 照片權限繼承派工，不因知道 URL／資產 ID 就可讀；L2-07 |
| 行政確認、退回補件、結案 | 管理 | 管理 | 只看本人回報結果；不可自審完工 | 補件不回寫已發生的資源釋放；異常交 L1 處理，L2-08 |
| 歷程、總覽 | 本公司全部 | 本公司業務；不讀認證敏感資料 | 本人有效任務內必要歷程 | 總覽／搜尋／分頁數量也依範圍計算，L2-09 |
| 成本、薪資、計費、全量匯出 | 首版無功能 | 首版無功能 | 首版無功能 | 不以超級管理員角色擴張未做的產品能力，L2-24 |

司機已撤派、已改派或已完成歷史的保存與可見期限不同：稽核可保存，但建議司機不另開全歷史查詢入口。若業務要求司機查歷史，須確認期限、欄位及照片存取後補入驗收。管理員也不能跳過業務狀態與資源占用規則。

## 司機手機與照片作業

建議採響應式手機網頁。驗收設備先列 iOS Safari 與 Android Chrome 各一台實機，正式支援版本在試點前記入驗收紀錄；桌面模擬器不代替實機。介面顯示繁體中文及台北時間，按鈕可觸控、表單無橫向溢出。

1. 登入後取得本人有效派工；點開只顯示該段必要資訊。重新整理保留後端真實狀態；Session 失效要求重新登入，不顯示成功。
2. 出發前重新驗證派工仍屬本人及資源狀態；調度改派與司機出發競爭只能有一個合法結果。
3. 到點完成該段作業後，拍照或選擇相簿上傳。畫面分開顯示上傳中、待驗證、可用、失敗；選好本機檔案不算已存檔。回報按鈕只接受後端已驗證且屬該派工的資產 ID。
4. 建議每段作業回報至少一張憑證：送貨段用交付憑證、提還櫃段用場站／交接憑證，不將每段都稱為客戶簽收。初始上限建議每段 5 張、單張原檔 10 MiB，接受 JPEG／PNG；HEIC 須明確轉換為可驗證格式或提示不支援，不能只改副檔名。以上數值與格式為 D06 待核准參數，需以實機樣本及容量估算核對。
5. 回報失敗可重試；重複送出不得新增第二次回報或釋放兩次資源。網路中斷時明示尚未送達，保留目前頁面可行的暫存狀態；不承諾關閉瀏覽器後可恢復，也不做背景／離線排隊。人工改採電話通報時，必須由核定人依例外流程補登，不假裝系統已收到。
6. 調度查核照片與作業資訊，確認或退回補件並記原因。原回報、原照片及修改歷程保留；重新回報不覆蓋已釋放資源或將完成任務直接退回執行。照片存期、備份、刪除及復原責任由 L4 定義並核准後納上線門檻。

手機／照片驗收補充：驗證實際檔案內容與大小，不只依 Content-Type；拒絕偽裝檔及他人資產；上傳成功但驗證失敗不可回報；未提交的孤立上傳依核定暫存期限清理。限制原圖及縮圖存取；GPS／EXIF 不作第一版定位功能，也不默認需要保留定位資訊，是否移除敏感 metadata 待照片政策核准。

## 核准與驗收交接

決策紀錄至少記「D ID、使用者原意、採用／調整內容、核准者、日期、影響 L2 驗收 ID」。無回覆維持待決。驗收紀錄每項需記版本、資料集、步驟、實際結果及證據；將通過、失敗、未執行分開，不能以文件檢查代替產品驗收。

目前可完成的是範圍提案與追溯表；本 repo 尚無新版程式，本輪全部 L2 功能驗收均未執行。首要待決為單公司及外包邊界、每段照片必填與例外、板車是否首版必需。裝置／參數可在規格評審時一併確認；正式保存及復原依 L4，不先承諾無依據期限。
