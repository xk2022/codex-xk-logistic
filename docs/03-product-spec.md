# 產品規格草案 v0.1

狀態：待確認。下列第一版範圍均為建議，只有前後端分離與先規格後實作為已確認。

## 定位與角色

建議先做單一物流公司的內部運輸管理平台，繁體中文，Asia/Taipei，管理端以桌機效率為主，司機端適配手機。

| 角色 | 建議權限 | 資料範圍 |
|---|---|---|
| 系統管理員 | 帳號、角色、權限、設定與全部業務 | 公司內全部 |
| 調度員 | 客戶、訂單、車輛司機、派工、完工確認 | 公司內業務 |
| 司機 | 本人上下線、本人任務、出發與簽收 | 只限被指派本人任務 |
| 查詢人員（選配） | 業務唯讀 | 依核定範圍 |

API 必須檢查權限與資料範圍；隱藏按鈕不是授權。帳號與司機是不同資料，停權帳號不能繼續操作司機端。

## 建議 MVP

| 模組 | 功能與主要畫面 | 完成標準 |
|---|---|---|
| 認證 | 登入、登出、本人設定與密碼修改 | 真實 Session、錯誤與到期處理 |
| UPMS | 帳號／角色／權限列表、編輯、啟停與指派 | 未授權直接打 API 亦被拒絕 |
| CRM | 客戶列表、明細、編輯、主要聯絡人與地址 | 訂單能選有效客戶並保存名稱快照 |
| TOM | 訂單列表、建立、明細、受理、取消、歷程 | 篩選分頁、資料持久化、合法狀態流轉 |
| 貨櫃與任務 | 櫃項／任務清單與建立 | 是否納 MVP 及基數由 D03／D04 決定 |
| FMS | 車輛／司機列表、明細、編輯、狀態 | 重複車牌／電話與無效狀態被拒絕 |
| 調度 | 待派清單、選車司機、派工、進度、撤派／改派 | 占用衝突不重複派工；例外規則由 D05 決定 |
| 司機 | 我的任務、詳情、上下線、出發、簽收 | 僅本人任務；照片是否必填由 D06 決定 |
| 完工 | 待確認簽收、確認完成與訂單結案 | 資源正確釋放、歷程完整 |
| ADM | 字典分類／項目、啟停、排序、系統參數 | 停用項目不供新增，但歷史可顯示 |
| 總覽 | 待受理、待派、執行中、待確認 | 數量與後端查詢一致 |

共用互動：載入、無資料、錯誤、重試、欄位驗證、重複送出防護、版本衝突提示；不得將取資料失敗顯示成查無資料。列表支援後端分頁、關鍵字、狀態、日期與客戶篩選，具體適用欄位依頁面定義。

## 保存但不預設進入 MVP 的候選

- 多公司／分公司／外包車隊、客戶登入與線上下單。
- 港口、碼頭、場站主檔；進場時段、容量、作業與櫃型限制。
- 合約模板、固定／按量／里程／時間／混合計費、費用結算。
- 薪資、電子發票、GPS、即時追蹤、路線最佳化。
- 車頭與板車獨立管理、維修保養、里程、保險與證照到期。
- 報表匯出、通知、離線回報與推播。

上述項目來自 L8 介面／型別或前一輪討論；沒有因出現在舊畫面就自動成為第一版承諾。
